## 2. 대회와 평가 계약

예측 단위는 오디오 파일 1개다. 파일마다 다음 5개 확률을 0과 1 사이 값으로 출력한다.

| 열 | 의미 |
|---|---|
| `FILE_FAKE_PROB` | 파일 전체가 AI 생성 성분을 하나 이상 포함할 확률 |
| `VOICE_FAKE_PROB` | 음성 성분이 AI 생성일 확률 |
| `MUSIC_FAKE_PROB` | 음악 성분이 AI 생성일 확률 |
| `VOICE_PRESENT_PROB` | 음성이 존재할 확률 |
| `MUSIC_PRESENT_PROB` | 음악이 존재할 확률 |

공식 평가 데이터는 비공개 1,200개이며 길이 4~60초, 16 kHz, 모노·스테레오, MP3·WAV·FLAC 등으로 구성되고 일부 전화채널을 포함한다. 더미 ZIP의 조건은 이 실제 평가 분포를 대표하지 않는다.

```text
Score = 0.9 × ADS + 0.1 × CPS
ADS   = 0.5 × (1 - File EER)
      + 0.2 × (1 - Voice EER)
      + 0.3 × (1 - Music EER)
CPS   = 0.5 × Voice Presence ROC-AUC
      + 0.5 × Music Presence ROC-AUC
```

FAKE가 양성 1이며 Voice EER과 Music EER는 각 성분이 존재하는 샘플에만 계산한다. 공식 EER는 `roc_curve(..., drop_intermediate=False)`에서 `|FPR-FNR|`가 최소인 이산 지점을 선택한다. 점수는 클수록 좋다. Public은 테스트 100%이며 대회 종료 시점 Public이 Private가 된다.

3. 파일명·폴더·ID·길이·코덱·비트레이트·무음·음량이 라벨 또는 출처를 대리하는지 단변량 예측력과 교차표로 검사한다.
4. 출처, 화자·가수, 곡·발화, 세션, 생성기·체크포인트, 프롬프트, 후처리 계보를 매니페스트에 보존한다.

Train은 없고 실제 Test 1,200개는 비공개다. 따라서 정량 train/test 비교는 불가능하다. 더미는 전부 3.405초·WAV·모노·동일 콘텐츠이므로, 공식 실제 평가의 4~60초·다중 포맷·모노/스테레오·일부 전화채널 조건과 명백히 대표성이 다르다.

## 10. 검증 전략과 금지 사항

### 학습 데이터 확보 후 강제할 전략

1. `original_content_id`를 최상위 그룹으로 두고 파생본을 절대 분리하지 않는다.
2. 출처·화자·가수·곡·세션·생성기·체크포인트를 가능한 한 중첩 그룹으로 관리한다.
3. 그룹 제약 안에서 음성/음악 존재와 조건부 REAL/FAKE가 각 폴드에 모두 존재하도록 층화한다.
4. 일반 그룹 CV 외에 데이터셋 전체·생성기 전체를 제외하는 open-set 홀드아웃을 고정한다.
5. 공식 이산 EER와 성분 존재 마스크를 그대로 구현하고, 총점 외 5개 하위 지표와 출처·생성기·코덱·채널·길이별 지표를 보고한다.
6. 전처리 통계, 캘리브레이션, 임계값은 훈련 폴드에서만 적합한다.
7. MP3·FLAC, 스테레오, 전화채널, 4초와 60초 경계를 포함하는 별도 계약 테스트를 만든다.

### 금지할 방식

- 파일 또는 세그먼트 단순 무작위 분할
- 같은 원본·화자·곡·생성기의 파생본을 폴드 사이에 분산
- 이 더미 3개를 학습 또는 성능 검증에 사용
- 리더보드 점수로 반복 튜닝하거나 정답 분포를 역추정
- 비공개 테스트 배치 전체의 통계·순위·다른 파일 예측으로 보정
- 출처·버전·라이선스·실제 파일·생성 계보가 없는 데이터를 학습에 사용

### 검증 설계 자체의 독립성 감사

제안한 내부 검증에도 두 가지 누수 패턴이 남을 수 있다.

- **Shared-pool bias**: 파일 그룹만 분리해도 Train과 Validation이 같은 데이터셋·라벨러·수집 파이프라인에서 나오면 같은 편향을 공유한다. 독립적인 원천 데이터셋 및 생성기 전체 홀드아웃을 별도로 두고, 최종 판단은 주최 측의 비공개 정답·공식 scorer처럼 팀 밖에서 들어오는 ground truth에 연결해야 한다.
- **Wrong null hypothesis**: 코덱 열만 균형화해도 배경음·마이크·무음·후처리 등 같은 원천 흔적이 남으면 코덱 교란 제거 대조군이 아니다. 같은 원본을 여러 코덱·채널로 교차 재인코딩한 paired control과 원천 전체 홀드아웃을 함께 사용해야 한다.

이 독립성 조건이 없는 높은 내부 점수는 실제 생성 탐지 성능의 근거로 채택하지 않는다.

## 11. 감사 범위·재현성·한계

- ZIP 메타데이터, 안전 경로, 확장자·서명, 멤버 SHA-256과 CRC는 외부·중첩 ZIP의 모든 파일을 전수 검사했다.
- 3개 WAV의 모든 PCM 샘플을 읽어 무음·클리핑·RMS·peak를 전수 계산했다.
- 콘텐츠 표본추출은 하지 않았으므로 seed와 층화 기준은 해당 없음이다.
- 4.56GB 대부분이 모델 가중치지만 가중치의 성능·안전성·라이선스 적합성은 데이터 준비 감사 범위를 벗어난다. 파일 무결성과 포함 라이선스·메타데이터 존재만 확인했다.
- 원본 다운로드의 정확한 시각과 공식 게시 SHA-256은 확인할 수 없다.
- 실제 평가 오디오와 정답은 비공개이므로 검사하지 않았다.

## 12. 최종 게이트

### 확인한 사실

- 현재 `open.zip`은 공식 문서 구조와 일치하고 외부·중첩 ZIP 무결성이 정상이다.
- 공식 형식 예시에는 더미 WAV 3개와 샘플 제출 CSV가 있고, 중첩 ZIP에는 참고용 코드·모델이 있다.
- 라벨 학습 오디오와 학습 타깃은 0개다.
- 더미 WAV 3개는 서로 완전히 동일한 3.405초 모노 16 kHz PCM이다.
- 공식 규칙·평가·일정·FAQ를 2026-08-30에 재확인했다.

### 아직 확인하지 못한 사항

- 사용할 학습 코퍼스의 출처·라이선스·버전·실제 파일
- REAL/FAKE 및 성분 존재 라벨의 정의·품질·분포·일관성
- 원본·화자·곡·생성기·체크포인트·후처리 계보
- 학습 코퍼스의 오디오 품질, 중복, 누수, 분포 이동
- 공식 사이트가 게시하지 않은 배포 ZIP 기준 SHA-256

### 치명적 위험

- 형식 예시 ZIP을 학습 데이터로 오인하면 모델은 학습할 정답이 없고, 중복 더미를 독립 표본으로 잘못 세게 된다.
- 데이터 소스 등록 없이 학습을 시작하면 2차 평가의 실제 학습 파일·출처 제출 요건을 복원하기 어렵다.
- 계보 없는 무작위 분할은 동일 원본·화자·곡·생성기 파생본 누수로 검증 점수를 심각하게 부풀릴 수 있다.

### 최소 사용자 조치

1. 이 `open.zip`은 **학습 데이터가 아니라 공식 형식·베이스라인 참조본**으로만 보존하고, 내용 변경 없이 `data/raw/deepvoice/official-2026-08-30/open.zip`으로 옮긴다.
2. 이동 후 원본의 크기와 SHA-256이 현재 값과 같은지 다시 확인해 매니페스트 경로를 갱신한다.
3. 실제로 사용할 공개 REAL/FAKE 음성·음악·혼합 데이터의 `SOURCE_URL`, 라이선스, 버전·리비전, 로컬 경로와 용도를 `deepvoice/docs/DATA_SOURCES.csv`에 등록한다.
4. 실제 오디오, 5개 대회 타깃으로 변환 가능한 라벨, 원본·화자·곡·생성기·파생 계보 매니페스트를 함께 제공한다.
