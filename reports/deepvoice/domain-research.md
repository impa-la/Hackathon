# 딥보이스 탐지 도메인 조사

- 조사일: 2026-08-30
- 상태: 문헌 조사는 완료했으나 대회 데이터 검사는 원본 부재로 차단됨
- 적용 범위: 딥페이크 음성, AI 생성 음악, 음성·음악 혼합, 전화·코덱·후처리 환경

## 1. 대회가 정의한 생성·라벨링 메커니즘

대회는 오디오를 음성 단독, 음악 단독, 혼합으로 구분한다. 보컬은 음성으로 취급한다. AI가 생성한 음성 또는 음악 성분은 FAKE이며, 둘 중 하나라도 FAKE이면 파일 전체도 FAKE다. 품질 개선, 잡음 제거, 음량 조정처럼 새 성분을 만들지 않는 후처리는 REAL이다.

이 정의는 단순한 파일 이진 분류가 아니다. 성분 존재 여부 2개와 조건부 진위 2개, 파일 전체 진위 1개가 연결된 계층적 다중 과제다. 특히 `VOICE_FAKE`와 `MUSIC_FAKE`는 해당 성분이 있는 표본에서만 EER가 계산된다. 학습 데이터에서는 성분 부재 시 진위 라벨을 결측/마스크로 다루고, 파일 전체 라벨이 존재 성분의 진위와 논리적으로 일치하는지 검사해야 한다.

근거: [DACON 공식 설명](https://dacon.io/competitions/official/236749/overview/description), [DACON 공식 평가](https://dacon.io/competitions/official/236749/overview/evaluation)

## 2. 데이터 생성에서 생기는 주요 교란요인

### 생성기와 원천 데이터셋

음성 딥페이크 탐지는 같은 데이터셋 안에서는 좋아도 다른 실제 데이터·생성기에서 급격히 나빠질 수 있다. Interspeech 2022 연구는 기존 탐지기가 실세계 수집 데이터에서 최대 10배 수준의 상대적 성능 저하를 보였다고 보고했다. Interspeech 2024 연구는 ASVspoof 실험에서 새 딥페이크가 단순히 더 어려워서가 아니라 생성 방식의 차이 자체가 일반화 격차의 주된 요인이라고 분석했다.

따라서 모델 용량보다 먼저 출처·생성기·체크포인트를 그룹으로 관리하고, 생성기 전체를 제외하는 검증을 해야 한다. 단, 두 연구는 음성 중심이므로 음악 성분에 대한 직접 근거는 아니다.

근거: [Müller et al., Interspeech 2022](https://www.isca-archive.org/interspeech_2022/muller22_interspeech.html), [Müller et al., Interspeech 2024](https://www.isca-archive.org/interspeech_2024/muller24b_interspeech.html)

### 코덱, 전송, 전화 채널

ASVspoof 2021은 실환경을 반영하기 위해 인코딩·전송·압축 조건을 명시적으로 평가했다. 공식 사후 분석은 딥페이크 트랙의 시스템이 압축에는 일부 견고했지만 원천 데이터셋 간 일반화가 부족했다고 보고한다. 이번 대회도 MP3/WAV/FLAC, 모노/스테레오, 일부 전화채널을 명시하므로 포맷·비트레이트·채널을 타깃과 독립적으로 균형화하고 별도 스트레스 테스트를 해야 한다.

코덱 흔적은 진짜 생성 여부가 아니라 데이터 수집 파이프라인을 식별하는 지름길이 될 수 있다. REAL과 FAKE를 서로 다른 코덱 품질로 수집하면 검증 점수는 높아져도 비공개 평가에서 무너질 수 있다.

근거: [ASVspoof 2021 공식 페이지](https://www.asvspoof.org/index2021.html), [Liu et al., IEEE/ACM TASLP 2023](https://doi.org/10.1109/TASLP.2023.3285283)

### 새로운 신경 코덱 기반 생성

Codecfake 연구는 신경 코덱에서 직접 파형을 생성하는 계열이 기존 보코더 기반 생성과 다른 흔적을 낳아 기존 탐지기에 도전이 된다고 설명한다. 이는 생성 계열을 단순히 FAKE 한 클래스로 섞은 무작위 분할이 open-set 성능을 과대평가할 수 있음을 뒷받침한다.

근거: [Lu et al., Interspeech 2024](https://www.isca-archive.org/interspeech_2024/lu24f_interspeech.html)

### 실제 원천의 다양성

Interspeech 2025의 bona fide cross-testing 연구는 많은 벤치마크가 깨끗한 낭독 음성 같은 좁은 실제 음성 환경에 의존하며, 단일 EER 집계가 표본 수가 많은 생성기를 과도하게 반영할 수 있다고 지적한다. 이 대회에서는 일반 발화, 보컬, 전화, 음악 원천이 섞이므로 REAL 쪽도 환경·화자·가수·곡·후처리별로 분해해 성능을 봐야 한다.

근거: [Kwok et al., Interspeech 2025](https://www.isca-archive.org/interspeech_2025/kwok25_interspeech.html)

## 3. 대표 신호와 잡음

### 탐지에 유용할 수 있지만 교란과 구분해야 하는 신호

- 생성 파이프라인이 남기는 시간·주파수 불연속 또는 위상·고주파 특성
- 운율, 발음, 보컬 표현의 비자연성
- 음성·음악 경계와 혼합 구간에서의 불연속
- 파일 내부 여러 구간에서 반복되는 생성 흔적

### 지름길이 되기 쉬운 잡음

- 데이터셋 고유 배경음·마이크·방·전화망
- 파일 포맷, 인코더, 비트레이트, 태그, 헤더
- 길이, 무음 비율, 음량, 클리핑
- 파일명·폴더명·ID 순서
- REAL/FAKE 수집 시점과 후처리 도구 차이

현재 원본이 없으므로 어느 신호도 이 대회에서 유효하다고 확인되지 않았다. 모든 항목은 그룹 홀드아웃과 교란 균형화로 반증 가능한 검사로 다뤄야 한다.

## 4. 평가 관행과 함정

### EER의 조건부 표본 수

Voice EER과 Music EER은 성분 존재 표본에 한정된다. 각 폴드에서 조건부 양성·음성이 충분하지 않으면 EER이 불안정하거나 정의되지 않는다. 전체 표본의 클래스 비율만 맞추는 층화로는 부족하다.

### 단일 평균의 맹점

총점은 File EER 항목에 실질적으로 0.45, Voice EER에 0.18, Music EER에 0.27, 음성·음악 존재 AUC에 각각 0.05의 가중치를 둔다. 이 가중치는 평가 중요도이지 학습 손실 가중치가 자동으로 같아야 한다는 뜻은 아니다. 그룹별 표본 수가 다르면 단일 EER가 특정 생성기·원천을 과대표현할 수 있으므로 생성기·출처·채널별 EER와 부트스트랩 구간을 병기해야 한다.

### 리더보드 과적합

공식 설명은 Public Score가 전체 테스트 100%이고 종료 시 같은 점수가 Private로 전환된다고 한다. 하루 3회 제출을 반복해 설계를 선택하면 사실상 공개 평가셋에 과적합할 수 있다. 내부 검증 프로토콜을 고정하고 리더보드는 최종 실행 계약 확인용으로 제한해야 한다.

### 파일 독립성

대회는 다른 평가 파일의 통계나 예측을 사용하는 보정을 금지한다. 테스트 배치 전체 정규화, 테스트 분포 기반 임계값 선택, 순위 재조정, 서로 다른 파일 간 최근접 검색은 모두 금지 대상으로 취급해야 한다. 한 파일 내부의 세그먼트 집계만 허용된다.

## 5. 음악과 혼합 오디오에 대한 근거 공백

확인한 권위 있는 딥페이크 탐지 문헌 대부분은 음성에 초점을 둔다. 이번 대회는 보컬 없는 음악, 보컬+반주, 순차 혼합까지 평가하므로 음성 논문의 수치를 음악 탐지에 직접 외삽할 수 없다. AI 음악 데이터 후보를 선정할 때 생성 도구·버전·프롬프트·후처리·원곡 유사성·보컬 여부를 별도 계보로 기록하고, 곡·원본 단위 그룹 홀드아웃을 설계해야 한다.

이 근거 공백은 모델링 자유도가 아니라 추가 데이터 감사 필요성을 뜻한다.

## 6. 유사 벤치마크와 적용 한계

ASVspoof 2021 Speech Deepfake 데이터는 16 kHz FLAC 음성과 다양한 공격 알고리즘을 제공하며 채널·압축 일반화 연구에 유용하다. 그러나 이 대회의 음악·혼합·전화 조건과 라벨 체계를 그대로 대표하지 않는다. 외부 학습 후보로 사용할 경우 DACON의 공개 접근성·최소 비영리 허용 조건과 ASVspoof/원천 데이터 라이선스를 각각 확인하고, 평가 데이터와 겹치지 않는다는 근거를 남겨야 한다.

근거: [ASVspoof 2021 공식 페이지](https://www.asvspoof.org/index2021.html), [ASVspoof 2021 평가 계획](https://www.asvspoof.org/asvspoof2021/asvspoof2021_evaluation_plan.pdf)

## 7. 출처·재현·보존 제약

DACON 운영진의 2026-08-27 답변은 직접 생성한 오디오를 포함해 실제 학습에 사용한 데이터 파일 전부와 생성 스크립트, 모델 정보, 버전·리비전, 시드, 프롬프트, 후처리 파라미터를 2차 평가 때 함께 제출해야 하며, 재현 정보만으로 실제 파일을 대체할 수 없다고 명시한다. 따라서 생성 데이터도 일회성 산출물이 아니다. 최종 학습 파일 목록과 SHA-256을 실험별로 고정하고, 정제·제외 후 최종 사용분을 재현 가능하게 보존해야 한다.

근거: [학습 데이터 제출에 대한 DACON 운영진 답변](https://dacon.io/competitions/official/236749/talkboard/417198)

## 8. 데이터 확보 후 우선 검사

1. 모든 파일의 SHA-256, 포맷 서명, 디코딩 성공, 길이, 샘플레이트, 채널을 전수 검사한다.
2. 음성/음악/혼합과 REAL/FAKE의 교차표를 만들고 조건부 클래스 수를 계산한다.
3. 동일 바이트, 지각적 오디오 중복, 원본·재인코딩·세그먼트 파생 관계를 찾는다.
4. 출처·화자·곡·생성기·코덱·전화·후처리와 타깃의 연관을 수치화한다.
5. 출처/생성기/원본 그룹 홀드아웃에서 공식 5개 지표를 재계산한다.
6. 혼합 유형, 길이, 무음, 채널, 포맷별 오류를 비교한다.
7. 문헌 가설이 실제 데이터에서 성립하지 않으면 폐기한다.

## 9. 결론

현재 확정할 수 있는 최상위 도메인 제약은 생성기·원천·코덱·채널·원본 콘텐츠를 그룹으로 관리하고, 파일별 독립 추론과 조건부 EER 평가를 그대로 재현해야 한다는 점이다. 그러나 학습 데이터와 공식 더미 패키지가 없으므로 어떤 분포·품질 문제도 실제로 확인하지 못했다. 모델링은 `DATA_READINESS: READY` 재감사 전까지 시작하면 안 된다.
