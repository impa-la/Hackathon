# 딥보이스 탐지 도메인 조사와 실제 데이터 대응

- 조사·재확인일: 2026-08-30
- 상태: 공식 계약과 도메인 조사는 확인했으나 실제 학습 코퍼스가 없어 데이터 준비는 차단됨
- 실제 검사 대상: 공식 형식 예시 `open.zip`의 더미 WAV 3개와 참고 베이스라인

## 1. 대회 라벨 생성 메커니즘

대회는 오디오를 음성, 음악, 혼합으로 구분한다. 보컬은 음성이며 보컬과 반주가 함께 있으면 혼합이다. AI 생성 음성 또는 음악이 하나라도 있으면 파일 전체가 FAKE다. 새 성분을 만들지 않는 잡음 제거·품질 개선·음량 조정만 적용된 실제 원천은 REAL이다.

이는 단순 이진 분류가 아니라 성분 존재 2개, 성분별 조건부 진위 2개, 파일 전체 진위 1개의 계층적 라벨이다. 실제 학습 데이터에서는 성분 부재 시 성분 진위 손실·평가를 마스킹하고 다음 논리 일관성을 검사해야 한다.

```text
FILE_FAKE = (VOICE_PRESENT AND VOICE_FAKE)
         OR (MUSIC_PRESENT AND MUSIC_FAKE)
```

공식 근거: [대회 설명](https://dacon.io/competitions/official/236749/overview/description), [평가](https://dacon.io/competitions/official/236749/overview/evaluation)

실제 결과: 현재 CSV는 예측 템플릿뿐이며 라벨 행은 0개다. 따라서 논리 일관성과 라벨 노이즈를 검사할 수 없다.

## 2. 생성기·원천 이동

실세계 음성 딥페이크 탐지 연구는 벤치마크 내부 성능이 다른 원천·실환경으로 이동할 때 크게 저하될 수 있음을 보였다. 후속 ASVspoof 분석은 새 공격의 단순 난이도뿐 아니라 생성 방식 차이가 일반화 격차를 만든다고 보고했다.

근거: [Müller et al., Interspeech 2022](https://www.isca-archive.org/interspeech_2022/muller22_interspeech.html), [Müller et al., Interspeech 2024](https://www.isca-archive.org/interspeech_2024/muller24b_interspeech.html)

실제 검사: 생성기·원천이 있는 학습 데이터가 0개라 검증하지 못했다. 확보 후 생성기·체크포인트·원천 데이터셋 전체를 제외하는 홀드아웃이 필요하다. 두 연구는 음성 중심이므로 음악에 직접 일반화할 수 없다.

## 3. 코덱·전송·전화채널 교란

ASVspoof 2021은 실제 환경을 반영하기 위해 인코딩·전송·압축 조건을 명시적으로 포함했다. 공식 사후 분석은 압축 견고성과 원천 데이터셋 일반화가 서로 다른 문제임을 보여준다. 코덱·비트레이트·전화망은 생성 여부가 아니라 수집 파이프라인을 식별하는 지름길이 될 수 있다.

근거: [ASVspoof 2021 공식 페이지](https://www.asvspoof.org/index2021.html), [Liu et al., IEEE/ACM TASLP 2023](https://doi.org/10.1109/TASLP.2023.3285283)

실제 결과: 더미 3개는 모두 같은 16 kHz 모노 PCM WAV다. MP3·FLAC·스테레오·전화채널은 0개여서 실제 평가 조건을 대표하지 않는다. 실제 학습 데이터에서 포맷·비트레이트·채널·전화 여부와 타깃의 연관을 측정하고 교란을 균형화해야 한다.

## 4. 신경 코덱 기반 생성과 open-set 위험

Codecfake 연구는 신경 코덱 기반 생성이 기존 보코더 계열과 다른 탐지 문제를 만들 수 있음을 보였다. 생성 계열을 모두 섞은 파일 무작위 분할은 미관측 생성기에 대한 성능을 과대평가할 수 있다.

근거: [Lu et al., Interspeech 2024](https://www.isca-archive.org/interspeech_2024/lu24f_interspeech.html)

실제 검사: 생성기 메타데이터와 학습 FAKE 파일이 없어 미검사다. 생성 방식 계열과 체크포인트를 계보 키로 보존해야 한다.

## 5. 실제 원천 다양성과 EER 집계

최근 bona fide cross-testing 연구는 좁은 실제 음성 환경과 생성기별 표본 불균형이 단일 EER를 낙관적으로 만들 수 있음을 지적한다. 이번 대회는 일반 발화, 보컬, 음악, 혼합, 전화환경까지 포함하므로 REAL도 화자·가수·곡·환경·후처리별로 분해해야 한다.

근거: [Kwok et al., Interspeech 2025](https://www.isca-archive.org/interspeech_2025/kwok25_interspeech.html)

실제 검사: 더미의 고유 콘텐츠는 1개뿐이고 라벨이 없다. REAL 다양성이나 그룹별 EER를 평가할 수 없다.

## 6. 길이·무음·클리핑·중복의 역할

길이, 무음, 음량, 클리핑은 생성 흔적일 수도 있지만 수집·후처리 파이프라인의 대리변수일 가능성이 크다. 타깃별로 출처와 조건을 균형화하지 않으면 모델이 생성 여부보다 데이터셋을 맞힐 수 있다.

실제 결과:

- 더미 길이: 모두 3.405초로 실제 평가 최소 4초 미만
- 무음 비율: 모두 24.5319383% (`abs(x)<1e-4`)
- 클리핑: 모두 0%
- SHA-256: 세 파일 전부 동일

이 값은 형식 예시의 속성일 뿐 실제 평가 분포의 근거가 아니다. 세 ID를 독립 원본으로 세어서는 안 된다.

## 7. 평가 함정

### 조건부 EER

Voice EER와 Music EER는 성분 존재 샘플에만 계산된다. 각 검증 폴드에 다음 네 조건이 모두 있어야 한다.

- 음성 존재 ∩ 음성 REAL
- 음성 존재 ∩ 음성 FAKE
- 음악 존재 ∩ 음악 REAL
- 음악 존재 ∩ 음악 FAKE

그룹을 먼저 지킨 뒤 이 조건을 층화해야 한다. 전체 FILE_FAKE 비율만 맞추는 것은 충분하지 않다.

### 리더보드 과적합

Public이 테스트 100%이며 종료 시 같은 점수가 Private가 된다. 내부 검증 없이 하루 최대 3회 제출을 설계 선택에 사용하면 공개 평가셋에 과적합될 수 있다. 리더보드는 실행 계약 확인과 사전에 고정한 소수 모델 비교에만 사용해야 한다.

### 파일 독립성

다른 평가 파일의 통계·예측을 이용한 보정은 금지된다. 테스트 배치 전체 정규화, 테스트 분포 기반 임계값, 순위 재조정, 파일 간 최근접 검색을 금지해야 한다. 한 파일 내부 세그먼트 집계만 허용된다.

## 8. 음악·혼합 오디오의 근거 공백

확인한 권위 있는 공개 딥페이크 탐지 문헌의 상당수는 음성 중심이다. 음성 결과를 보컬 없는 음악, 보컬+반주, 순차 혼합에 그대로 외삽할 수 없다. AI 음악 데이터는 생성 도구·버전·프롬프트·후처리·원곡 유사성·보컬 여부를 별도 계보로 관리해야 한다.

현재 `open.zip`에는 음악·혼합 유형 라벨이 없으므로 이 공백을 실제 데이터로 줄이지 못했다.

## 9. 외부 자원과 보존 규칙

공식 규칙은 공개 접근 가능하고 최소 비영리 사용이 허용된 자원을 라이선스 조건 준수 아래 허용한다. 운영진은 CC-BY-NC와 CC-BY-NC-SA도 이 조건을 만족하면 사용할 수 있다고 답했다. 2차 평가에서는 직접 생성한 오디오를 포함해 실제 학습 파일 전체와 생성·재현 정보를 제출해야 한다.

근거: [공식 규칙](https://dacon.io/competitions/official/236749/overview/rules), [라이선스 답변](https://dacon.io/competitions/official/236749/talkboard/417212), [학습 파일 제출 답변](https://dacon.io/competitions/official/236749/talkboard/417198)

영향: 데이터 수집 첫날부터 URL, 버전·리비전, 라이선스, 실제 파일 SHA-256, 원본·파생 계보를 기록해야 한다. 사용 가능한 라이선스라는 운영진 답변은 원천 데이터의 재배포·저작인접권·인물 음성 권리 검토를 대신하지 않는다.

## 10. 결론

문헌과 공식 규칙이 공통으로 요구하는 최상위 제약은 원본·출처·화자·곡·생성기·코덱 계보를 보존하고, 그룹·open-set 검증과 파일별 독립 추론을 강제하는 것이다. 그러나 현재 `open.zip`은 라벨 학습 데이터가 아니므로 이 제약을 실제 학습 코퍼스에 적용해 검증할 수 없다.

도메인 조사만으로 `READY`가 되지 않는다. 실제 학습 데이터와 라벨·계보를 확보하고 재감사해야 한다.
